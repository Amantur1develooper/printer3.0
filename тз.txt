Ниже готовое ТЗ для системы онлайн-принтера, часть сайта

Техническое задание
Проект: Онлайн-принтер
1. Цель проекта

Создать систему, в которой пользователь загружает документ через сайт, система автоматически определяет количество листов, рассчитывает стоимость печати, принимает оплату, после чего отправляет задание на ноутбук, подключённый к принтеру, и документ печатается.

2. Общая схема работы
Пользователь заходит на сайт.
Загружает файл.
Система определяет количество страниц и листов.
Система рассчитывает стоимость печати.
Пользователь выбирает параметры печати.
Пользователь оплачивает заказ.
Заказ поступает в очередь печати.
Ноутбук, подключённый к принтеру, получает задание с сервера.
Ноутбук скачивает файл и отправляет его на печать.
Сайт получает статус печати и показывает результат.
ЧАСТЬ 1. ТЗ ДЛЯ САЙТА
3. Основной функционал сайта
3.1. Загрузка файла

Сайт должен позволять пользователю:

загрузить документ для печати;
видеть название файла;
видеть формат файла;
видеть количество страниц;
видеть предварительный расчёт стоимости.
3.2. Поддерживаемые форматы

Для первой версии желательно сделать:

PDF — обязательно;
DOCX — как дополнительный формат позже;
JPG, PNG — по желанию позже.

Рекомендация для первой версии:
в MVP принимать только PDF, потому что:

проще и точнее считать страницы;
проще печатать;
меньше ошибок при форматировании.
4. Подсчёт листов и страниц
4.1. Логика подсчёта

После загрузки файла система должна автоматически определить:

количество страниц документа;
количество листов для печати;
итоговую стоимость.
4.2. Формулы
Односторонняя печать:
листы = количество страниц
Двусторонняя печать:
листы = ceil(количество страниц / 2)
Итоговая стоимость:

стоимость = (листы × цена_за_лист × количество_копий) + дополнительные_опции

5. Параметры печати на сайте

Пользователь должен иметь возможность выбрать:

5.1. Основные параметры
количество копий;
цвет печати:
черно-белая;
цветная;
тип печати:
односторонняя;
двусторонняя;
формат бумаги:
A4;
A3 в будущем;
диапазон страниц:
все страницы;
отдельные страницы;
ориентация:
как в документе;
принудительно портрет;
принудительно альбом.
5.2. Дополнительные параметры
печатать только чётные страницы;
печатать только нечётные страницы;
скрепление/степлер — на будущее;
выбор качества печати — на будущее.
6. Расчёт стоимости

Сайт должен автоматически считать цену в зависимости от:

количества листов;
количества копий;
цветности;
односторонней или двусторонней печати;
выбранного формата бумаги.
6.1. Пример тарифов

Администратор должен иметь возможность задавать тарифы:

A4 ч/б односторонняя — 5 сом за лист;
A4 ч/б двусторонняя — 4 сом за лист;
A4 цветная односторонняя — 15 сом за лист;
A4 цветная двусторонняя — 12 сом за лист.
6.2. Что должен видеть пользователь

После выбора параметров пользователь должен видеть:

страниц: 12;
листов: 6;
копий: 2;
тип: двусторонняя;
цвет: черно-белая;
итог: 48 сом.
7. Оформление заказа

Перед оплатой пользователь должен заполнить:

имя;
номер телефона;
при необходимости email;
комментарий к заказу.

Система создаёт заказ со статусом:

created — создан;
uploaded — файл загружен;
calculated — стоимость рассчитана;
awaiting_payment — ожидает оплату;
paid — оплачен;
queued — в очереди печати;
printing — печатается;
printed — распечатан;
error — ошибка;
cancelled — отменён.
8. Оплата

Сайт должен поддерживать оплату заказа.

8.1. Логика оплаты
до оплаты печать не запускается;
после подтверждения оплаты заказ автоматически переводится в статус paid;
затем создаётся задача на печать.
8.2. Требования
хранить номер транзакции;
хранить сумму оплаты;
хранить дату и время оплаты;
не отправлять заказ на печать при неполной оплате.
9. Личный кабинет / страница отслеживания

Пользователь должен видеть:

номер заказа;
название файла;
количество листов;
стоимость;
статус заказа;
время создания заказа;
время печати;
сообщение об ошибке, если печать не удалась.
10. Админ-панель сайта

Администратор должен иметь возможность:

просматривать все заказы;
видеть файл заказа;
видеть параметры печати;
менять тарифы;
видеть статус каждого заказа;
видеть, какой принтер или терминал должен печатать заказ;
вручную отменять заказ;
повторно отправлять заказ в очередь;
смотреть журнал ошибок;
смотреть статистику по выручке.
11. Статистика и отчёты

Сайт должен показывать:

количество заказов за день;
количество распечатанных листов за день;
сумму оплаченных заказов;
сумму отменённых заказов;
ошибки печати;
отчёт по каждому терминалу/принтеру.
12. Требования к безопасности сайта

Сайт должен:

принимать только разрешённые типы файлов;
ограничивать максимальный размер файла;
проверять файл до отправки в печать;
хранить заказы и оплаты в базе данных;
запрещать прямую печать без оплаты;
логировать все действия.
